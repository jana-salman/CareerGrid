# CareerGrid

CareerGrid is a Flask-based career-readiness platform that lets students
practice realistic workplace tasks and structured job interviews. It combines
a simulated desktop workspace, Firebase persistence, and Google Gemini
evaluation while keeping candidate-visible content separate from private
grading material.

## Main features

- Secure registration and login with Werkzeug password hashing
- Career, position, and company/job selection
- Backend Developer workplace scenarios generated by Gemini
- A deterministic TechNova Backend demo for presentations
- A five-step Frontend Developer workplace simulation with a deterministic
  fallback when generation is unavailable
- Simulated Mail, Files, VS Code, Terminal, Browser, Git, and GitHub tools
- Persisted workplace and interview attempts in Firebase Realtime Database
- AI-assisted workplace feedback and progressive advisor guidance
- Timed microphone-based interviews with transcription and speech analysis
- Server-side interview rubrics and final AI evaluation
- Dashboard history for saved attempts and reports

## Architecture

CareerGrid keeps browser presentation, route orchestration, services, and tests
separate without introducing a second frontend framework.

```text
CareerGrid/
├── app.py                         # Flask setup and application routes
├── routes/
│   └── auth.py                   # Authentication Blueprint
├── services/
│   ├── scenario_generation_service.py
│   ├── frontend_workplace_scenario_service.py
│   ├── backend_demo_scenario_service.py
│   ├── evaluation_service.py
│   ├── advisor_service.py
│   ├── interview_service.py
│   ├── simulation_storage.py
│   ├── firebase_service.py
│   ├── gemini_service.py
│   └── user_service.py
├── templates/                    # Jinja pages and simulation windows
├── static/
│   ├── css/
│   ├── js/
│   └── images/
├── tests/                        # Offline automated tests
├── .env.example                  # Placeholder configuration
├── requirements.txt              # Runtime dependencies
└── requirements-dev.txt          # Runtime plus test dependencies
```

`app.py` remains the route coordinator because the workplace and interview
flows share endpoint names, session state, and test seams. Authentication is
isolated in a Blueprint. Larger simulation and interview modules were left
intact where splitting them would create disproportionate regression risk.

## Workplace scenario validation

Both Backend and Frontend workplace scenarios now use the shared validation
pipeline in `services/scenario_generation_service.py`.

```text
Backend scenario service
        ↓
validate_workplace_scenario()

Frontend scenario service
        ↓
validate_workplace_scenario()
        ↓
validate_frontend_requirements()
```

The shared validator protects:

- Public/private context separation
- Relative project paths and path traversal
- Generic text-file extension allowlisting
- Unique project files and bounded file content
- Project naming and archive consistency
- Resource and attachment integrity
- Unsafe shell content and solution-leak patterns
- Scenario payload size

The focused Frontend validator retains only career-specific rules:

- Required HTML, CSS, JavaScript, and package files
- Frontend-only file extensions
- Five ordered workplace tasks and valid application names
- Exactly five inbox emails and one linked critical incident
- Allowed simulated terminal commands
- Viewport metadata
- Firebase-safe private expected-patch keys

## AI and evaluation flow

### Workplace scenarios

- Normal Backend jobs use Gemini scenario generation.
- The TechNova presentation job uses a predefined, validated Backend scenario.
- Frontend jobs use Gemini generation with the established deterministic
  five-step fallback when generation or validation fails.

All scenarios use the same Firebase attempt lifecycle and public/private
storage boundary. Only validated public scenario data is returned through the
candidate-facing attempt API.

### Workplace evaluation

The submission API combines actual candidate evidence—changed files, commits,
pull-request data, verification, and communication—with private server-side
expectations. Gemini produces the final evidence-based report. Scores are never
predefined for the Backend demo.

### Interviews

Normal interviews use seven Gemini-generated questions. The TechNova demo uses
four predefined questions, but microphone capture, transcription, spoken-answer
analysis, per-answer evaluation, Firebase storage, and final Gemini scoring all
remain live. A workplace score of at least 85 is required to unlock an
interview.

## Firebase data structure

CareerGrid uses Firebase Realtime Database and preserves the following
high-level hierarchy:

```text
users/{user_id}/
├── full_name
├── email
├── password_hash
├── simulation_attempts/{attempt_id}/
│   ├── public_scenario
│   ├── private_context
│   ├── responses
│   └── evaluation
└── interview_attempts/{interview_id}/
    ├── public_questions
    ├── private_rubrics
    ├── answers
    └── evaluation
```

Private context and rubrics remain server-side and are not included in browser
scenario responses or interview template data.

## Installation

### 1. Clone and enter the project

```bash
git clone https://github.com/jana-salman/CareerGrid.git
cd CareerGrid
```

### 2. Create a virtual environment

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

macOS or Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

For application use:

```bash
python -m pip install -r requirements.txt
```

For development and tests:

```bash
python -m pip install -r requirements-dev.txt
```

## Environment variables

Never commit `.env` or the Firebase service-account JSON file.

```env
CAREERGRID_ENV=development
FLASK_DEBUG=false
SECRET_KEY=replace_with_a_long_random_secret

GEMINI_API_KEY=replace_with_gemini_api_key
GEMINI_MODEL=gemini-3.1-flash-lite

ADZUNA_APP_ID=replace_with_adzuna_app_id
ADZUNA_APP_KEY=replace_with_adzuna_app_key

FIREBASE_DATABASE_URL=https://your-project-default-rtdb.firebaseio.com
GOOGLE_APPLICATION_CREDENTIALS=firebase-service-account.json
```

Generate a suitable local secret with:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

When `SECRET_KEY` is absent in development, CareerGrid creates a temporary
random key and warns that sessions will reset after restart. When
`CAREERGRID_ENV=production`, `SECRET_KEY` is required and startup fails clearly
if it is missing.

Adzuna credentials are optional. CareerGrid continues with local/demo job cards
when they are absent or the API is unavailable.

## Firebase setup

1. Create or select a Firebase project.
2. Enable Realtime Database.
3. Create a Firebase Admin service account.
4. Download the JSON credential file as `firebase-service-account.json` in the
   project root, or set `GOOGLE_APPLICATION_CREDENTIALS` to another local path.
5. Set `FIREBASE_DATABASE_URL` to the project Realtime Database URL.

The credential filename and common Firebase service-account patterns are
excluded by `.gitignore`.

## Gemini setup

1. Create a Gemini API key through Google AI Studio or the appropriate Google
   Cloud project.
2. Set `GEMINI_API_KEY` in `.env`.
3. Keep `GEMINI_MODEL` at the documented tested model or change it deliberately
   after validating compatibility.

To perform the optional live connectivity check:

```bash
python test_gemini.py
```

This command uses the external API and is intentionally separate from the
offline automated test suite.

## Running CareerGrid

```bash
python app.py
```

Open `http://127.0.0.1:5000` in a browser. Set `FLASK_DEBUG=true` only during
local development; debug mode is disabled by default.

## Running tests and checks

Run the complete offline suite:

```bash
python -m pytest -q
```

Run Python compilation checks:

```bash
python -m compileall -q .
```

If Node.js is installed, JavaScript syntax can be checked file by file with
`node --check <path-to-file.js>`.

Tests cover scenario validation and privacy, deterministic demo behavior,
Frontend five-step progression, storage contracts, evaluation, interview
question selection, and dynamic interview completion.

## Security and submission hygiene

- Passwords are stored only as Werkzeug hashes.
- User IDs are Firebase-safe SHA-256 identifiers derived from normalized email.
- Firebase reads and writes retain per-user attempt ownership paths.
- Public scenario APIs omit private evaluation context and interview rubrics.
- Generated paths, files, resources, commands, and attachments are validated.
- `.env`, service-account credentials, caches, bytecode, coverage files, and
  local databases are ignored.

For a clean final ZIP after committing the intended source changes:

```bash
git archive --format=zip --output CareerGrid-submission.zip HEAD
```

This exports tracked source files without `.git`, ignored secrets, or generated
cache directories.

## Known limitations and future improvements

- Career coverage is intentionally limited to the current university-project
  scope.
- Gemini and Firebase features require network access and valid credentials.
- Browser microphone support depends on permission and MediaRecorder support.
- The simulated terminal intentionally supports a controlled command set rather
  than executing arbitrary local programs.
- The large shared simulation-state modules remain candidates for future,
  separately tested decomposition after the final submission.
